Module 1 — Introduction, Structures and Stacks

Data structures, operations, C structures, array of structures, stack operations and expression notations.

Arrays

Student marks and image pixels

Scenario: Store marks for a class or pixel values for an image.

Why it fits: Indexed access makes reading or updating an element straightforward; traversing processes the collection one item at a time.

Structures / Array of Structures

Student, patient and product records

Scenario: Maintain USN, name, branch, semester and CGPA, or product ID, name, price and quantity.

Why it fits: A structure groups fields of different types; an array of structures stores many records of the same kind.

Stack · LIFO

Undo in a text editor

Scenario: Undo the most recent edit first.

Why it fits: The latest operation is on top and is removed first using POP. A second stack can support redo.

Stack · LIFO

Browser back history

Scenario: Return to the most recently visited page in a navigation sequence.

Why it fits: A stack naturally represents a last-visited-first-returned sequence.

Stack · Validation

Balanced brackets in code

Scenario: Check whether every opening bracket has a matching closing bracket.

Why it fits: Push opening brackets and pop when a matching closing bracket appears; the stack should finish empty.

Module 2 — Stack Applications, Recursion and Queues

Infix/postfix/prefix conversion, postfix evaluation, recursion, linear and circular queues, deques and priority queues.

Expression processing

Calculator and compiler expressions

Scenario: Convert an infix expression such as (A+B)*C into postfix or evaluate a postfix expression.

Why it fits: A stack temporarily stores operators or operands while respecting precedence and evaluation order.

Recursion · Interactive puzzle

Tower of Hanoi

Scenario: Move a stack of disks from one peg to another without placing a larger disk on a smaller one.

Why it fits: The solution recursively moves n−1 disks, moves the largest disk, then moves n−1 disks again.

Play the interactive Tower of Hanoi puzzle ↗

Recursion

Factorial and recursive calls

Scenario: Solve a problem by breaking it into smaller instances of the same problem.

Why it fits: Each call has its own state on the call stack and must eventually reach a base case.

Queue · FIFO

Bus boarding and service counters

Scenario: Passengers join a waiting line and the earliest waiting passenger is served first.

Why it fits: Enqueue adds at the rear and dequeue removes from the front, following FIFO.

Circular Queue

Elevator floor requests / round-robin tasks

Scenario: Reuse a fixed-size array as requests are added and processed.

Why it fits: Front and rear wrap around to the beginning, reusing freed positions.

Deque

Worklists with two-ended access

Scenario: Add or remove pending items at either end of a sequence.

Why it fits: A double-ended queue supports insertion and deletion at both front and rear.

Priority Queue

Urgent task scheduling

Scenario: Process higher-priority jobs before lower-priority jobs.

Why it fits: Removal is based on priority rather than arrival order alone.

Module 3 — Pointers, Dynamic Memory and Linked Lists

Dynamic memory allocation, self-referential structures, singly/doubly/circular linked lists and linked-list representations of stacks and queues.

Singly Linked List

Patient waiting list

Scenario: Store patient ID, name, age, disease and phone number while allowing records to be inserted or deleted.

Why it fits: Nodes can be linked dynamically without requiring a contiguous block of memory.

Doubly Linked List

Music playlist navigation

Scenario: Move forward to the next song or backward to the previous song.

Why it fits: Each node has both next and previous links; operations at both ends can also model deque behavior.

Circular Linked List

Round-robin turns

Scenario: Rotate repeatedly through players, processes or participants.

Why it fits: The last node links back to the first, allowing traversal to continue cyclically.

Linked Stack / Queue

Resizable collections

Scenario: Maintain a stack or queue when the number of items is not known in advance.

Why it fits: Linked nodes can be allocated as needed instead of relying on a fixed-size array.

Module 4 — Trees and Binary Search Trees

Tree terminology, binary trees, representations, traversals, threaded binary trees, BST operations and expression evaluation using trees.

Binary Tree

Hierarchical data

Scenario: Represent a hierarchy such as a decision structure or a family of related categories.

Why it fits: Parent-child links express hierarchical relationships.

Binary Search Tree

Ordered lookup

Scenario: Insert, search and traverse a set of keys while maintaining an ordering rule.

Why it fits: Values smaller than a node are placed to the left and larger values to the right (duplicates need a defined policy).

Tree Traversal

Expression evaluation

Scenario: Represent operators and operands as a tree and evaluate the expression.

Why it fits: Traversal order can produce infix, prefix or postfix forms, depending on the chosen traversal.

Module 5 — Graphs and Hashing

Graph terminology and representations, BFS/DFS traversals, hash tables, hash functions, collision handling, and static/dynamic hashing.

Graph · BFS / DFS

City and road connectivity

Scenario: Represent cities as vertices and roads as edges; find reachable cities or check connectivity.

Why it fits: Adjacency matrices or lists store connections; BFS and DFS explore reachable vertices.

Graph

Computer and social networks

Scenario: Model devices or people and the links between them.

Why it fits: Graphs represent relationships that are not limited to a single hierarchy.

Hashing

Product ID lookup

Scenario: Store supermarket products by unique IDs and locate records through a hash table.

Why it fits: A hash function maps a key to a table index; collisions can be handled with linear probing.

Hashing

Fast record retrieval

Scenario: Find a record by a key such as an ID or code.

Why it fits: Hash-based access can be efficient when the hash function and collision strategy are chosen appropriately.

Study tip: For each example, be ready to explain (1) what is stored, (2) which operations are needed, (3) why the selected structure fits, and (4) its limitation or trade-off.
